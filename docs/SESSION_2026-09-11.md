### CMS media library and in-builder image workflow

- `/admin/cms/media` is now a separate media-management screen: upload, search, category filtering, asset details, copy URL, and deletion. It contains no Website CMS Builder controls or instructions.
- Media is persisted per company/property with `CmsMediaAsset` and Rails Active Storage, not in a hard-coded frontend array.
- Supported media: JPG, PNG, WebP, and GIF images up to 10 MB. The server validates file type and size.
- Added authenticated Rails routes under `/api/v1/cms/media` for listing, uploading, and deleting assets. Each write is audited.
- Added Next.js multipart proxy support in `src/lib/rails-proxy.ts` and `src/app/api/cms/media/route.ts` so the browser's authenticated session is used safely for uploads.
- `/admin/cms/pages` now includes **Choose or upload image** controls inside both the Hero Cover Image and Offer Banner Image fields. The user can choose an existing upload or add one in that same CMS Builder modal; no visit to `/admin/cms/media` and no URL copy/paste is required for normal CMS edits.
- The Media Library remains useful as an optional central review/delete screen.

## Deployment/development cautions

- Never run `npm run build` while `npm run dev` is operating in the same checkout. The shared `.next` cache can become inconsistent, resulting in 404 CSS/JS chunks and 500 pages. Recovery: stop the Next process, remove only `D:\Laravel Projects\Freelancing\Hotel New Era\.next`, then restart `npm run dev`.
- The recent `npm run build` compiled successfully but static export still fails because existing public pages use `useSearchParams()` outside a Suspense boundary. Affected paths: `/`, `/about`, `/banquet`, `/book`, `/contact`, `/dining`, `/offers`, and `/rooms`. This is unrelated to the CMS media work.
- Media storage is local Rails Active Storage disk storage in development. Production must use a durable object store (for example S3-compatible storage) with backups and correct public URL/host configuration.
